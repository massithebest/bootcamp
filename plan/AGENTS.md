# 상위 계획 문서 지침

이 폴더는 백엔드와 프론트엔드를 아우르는 요구사항과 완료 조건의 기준이다.

- 기능 계획 파일명은 `<yymmdd>-<topic>-plan.md` 형식을 사용한다. 날짜는 최초
  작성일이며 완료 후에도 바꾸지 않는다. 프로젝트 요구사항과 진행 상태를 함께
  관리하는 `Todo.md`만 이 규칙의 예외다.
- 문서 상단에 상태와 마지막 갱신일을 적는다.
- 사용자 목표, 범위·비범위, 공유 API·데이터 계약, 파트별 할당, 의존 관계,
  전체 인수 조건을 기록한다.
- 구현 파일 목록과 세부 Task는 반복하지 않고 `backend/plan`과
  `frontend/plan`의 실행 계획으로 연결한다.
- 프로젝트 범위나 공통 계약이 변경되면 `Todo.md`를 먼저 갱신하고 관련 상위
  계획과 하위 계획의 상태를 맞춘다.
- 완료된 계획도 삭제하지 않는다. 후속 범위는 같은 문서의 새 단계 또는 새
  날짜형 계획으로 분리한다.
- 문서 동기화 작업은 현재 코드·환경 예시·패키지 버전과 링크를 근거로 수행하고,
  단순히 모든 파일의 수정 시각을 바꾸기 위한 의미 없는 편집은 하지 않는다.
