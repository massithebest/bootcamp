# Backend 계획 지침

이 폴더는 Backend workspace 안에서 독립적으로 관리한다. 루트 계획이나 Frontend
문서를 읽을 수 있다고 가정하지 않는다.

- 먼저 `Todo.md`에서 현재 계약, 미완료 작업과 완료 이력을 확인한다.
- 작은 작업은 `Todo.md`에 목표·Task·검증·상태를 직접 기록한다.
- 큰 작업만 `<yymmdd>-<topic>-plan.md`를 만들고 상태, 범위·비범위, 변경 대상,
  Backend가 제공할 API·payload, Task, 검증과 완료 조건을 문서 안에 완결한다.
- 다른 workspace 계획을 링크하거나 구현·배포 상태를 추정하지 않는다. 외부
  소비자에게 필요한 조건은 입력·출력·오류와 착수 조건으로 직접 적는다.
- 공개 계약을 변경하면 Backend schema·Tool·Fake Runner·테스트와 이 폴더의
  계약 설명을 같은 작업에서 갱신한다.
- 실행 중 결정과 실제 검증 결과를 남긴다. 완료 후 장기적으로 필요한 내용만
  `Todo.md`의 계약·완료 이력에 합치고 상세 계획은 제거한다.
- 문서만 바꾸면 링크·명령·현재 구현을 대조하고 `git diff --check`를 실행한다.
- 실행할 때는 `../AGENTS.md`의 폐쇄망·테스트·계층 규칙을 적용한다.
