# Backend 실행 계획 지침

- 상위 `../../plan/<yymmdd>-<topic>-plan.md`에서 할당된 백엔드 범위만 다룬다.
- 계획 파일명은 `<yymmdd>-<topic>-plan.md`이며 상단에 상태, 상위 계획과
  프론트 의존 관계를 적는다.
- 각 Task에는 변경 대상, 요구 동작, 검증 방법과 완료 조건을 포함한다.
- 공유 API와 payload를 다시 정의하지 말고 상위 계획을 링크한다. 계약 변경이
  필요하면 상위 계획을 먼저 갱신한다.
- 문서 끝에 결정 기록과 실제 검증 결과를 남긴다. 완료된 계획은 이력으로
  유지하며 사실 오류나 깨진 링크 외에는 실행 당시 결정을 소급해 바꾸지 않는다.
- 실행할 때는 `backend/AGENTS.md`의 폐쇄망·테스트·계층 규칙을 적용한다.
