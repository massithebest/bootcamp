# backend/plan/ 작업 지침

이 폴더는 백엔드 작업을 위한 **실행 계획 문서**를 모아둔다. 설계 판단이
끝난 뒤, 별도 세션(주로 저비용 모델)이 순서대로 실행할 수 있도록 Task
단위로 쓴 작업 목록이다. 상위 범위 지침은 [backend/CLAUDE.md](../CLAUDE.md)를
따른다.

## 문서 성격

- 이 폴더의 문서는 **설계 문서가 아니다.** 설계 판단은 `docs/`(최상위 또는
  `backend/docs/`)에 있는 설계 문서를 따른다. 계획 문서에서 설계와 어긋나는
  결정이 필요하면 멈추고 사용자에게 묻는다.
- 각 계획 문서는 자기 완결적이어야 한다 — 실행 세션이 이 문서만 읽고 시작할
  수 있게, 실행 방법·순서·검증 명령·완료 기준을 문서 안에 포함한다.
- 계획 문서 끝에는 실행 세션이 채우는 "결정 기록"(또는 동등한) 절을 둬서
  설계에 없던 결정이 무엇이었는지 남긴다.

## 새 계획 문서를 추가할 때

- 파일명은 `<yymmdd>-<주제>-plan.md` 형식을 따른다. `yymmdd`는 문서를 처음
  작성한 날짜다 (예: `260915-result-store-plan.md`). 날짜 접두사가 없는
  기존 문서(`domain-knowledge-plan.md`)는 소급 변경하지 않는다.
- Task 순서를 명시하고, 뒤 Task가 앞 Task의 산출물에 의존하면 그 의존성을
  문서에 적는다.
- 각 Task는 "파일", "스펙", "검증", "완료 기준"을 갖춘다.
- 완료된 계획은 삭제하지 않고 남겨서 이력으로 둔다. 상태를 문서 상단에
  `**상태: ...**` 형태로 표시한다 (예: 완료, 착수 대기, 진행 중).

## 실행 세션 시작 관례

계획 문서 실행을 새 세션에 맡길 때는 `backend/` 디렉토리에서 시작하고,
첫 프롬프트에 계획 문서 경로와 "Task 0부터 순서대로 진행" 지시를 명시한다.
자세한 예시는 각 계획 문서 상단의 "실행 세션 시작 방법" 절을 참고한다.

첫 프롬프트에는 **"설계에 없던 판단을 내릴 때마다 문서 끝 '결정 기록'
절에 바로 남겨라"는 지시를 반드시 포함한다.** 이 관례는 Claude Code로
실행할 때만이 아니라 다른 에이전트(Codex 등)에 맡길 때도 동일하게
적용한다 — 계획 문서가 도구 불문으로 자기 완결적이어야 하는 것과 같은
이유로, 실행 기록도 도구와 무관하게 저장소 관례를 따라야 한다.
