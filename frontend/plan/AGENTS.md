# Frontend 실행 계획 지침

- 상위 `../../plan/<yymmdd>-<topic>-plan.md`에서 할당된 프론트엔드 범위만 다룬다.
- 계획 파일명은 `<yymmdd>-<topic>-plan.md`이며 상단에 상태, 상위 계획,
  필요한 백엔드 계획과 착수 조건을 적는다.
- 각 Task에는 변경 대상, UI·상태·계약 동작, 검증 방법과 완료 조건을 포함한다.
- 공유 API와 payload를 다시 정의하지 말고 상위 계획을 링크한다. 백엔드 계약이
  준비되지 않았으면 더미 형태를 추측하지 않는다.
- 문서 끝에 결정·실행 기록과 실제 검증 결과를 남긴다. 완료된 계획은 이력으로
  유지하며 사실 오류나 깨진 링크 외에는 실행 당시 결정을 소급해 바꾸지 않는다.
- 문서만 바꾸는 작업은 링크·패키지 버전·명령·화면 용어를 현재 코드와 대조하고
  `git diff --check` 결과를 기록한다.
- 실행할 때는 `frontend/AGENTS.md`의 폐쇄망·assistant-ui·UI 검증 규칙을 적용한다.
