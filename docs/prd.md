# PRD — P&T FP Agent (생산계획 에이전트)

**상태: 진행 중.** 이 문서는 살아있는 문서로, 기능이 진행되거나 범위가
바뀔 때마다 갱신한다. 새 기능 영역이 시작되면 "5. 기능 요구사항" 표에
행을 추가하고, 상태가 바뀌면(설계 전 → 설계 완료 → 진행 중 → 완료) 그
표만 갱신한다. 완료된 항목도 삭제하지 않고 "완료" 상태로 남겨 이력을
보존한다.

## 1. 배경 / 문제 정의

제조 생산계획 업무는 SQL·시뮬레이션 툴·도메인 지식(용어, KPI 정의, 원인
진단 규칙)에 능숙한 소수 인력에게 의존한다. 비전문 사용자(계획 담당자,
현장 관리자)가 "이번 주 A라인 가동률이 왜 떨어졌지?" 같은 질문을 하려면
SQL을 짜거나 담당자에게 요청해야 한다.

이 프로젝트는 자연어로 생산계획 데이터를 질의하고, 필요하면 시뮬레이션을
실행하고, 결과를 표/차트로 확인할 수 있는 사내 에이전트 도구를 만든다.
최종 배포 환경은 **인터넷이 차단된 폐쇄망**이며, 이 제약이 전체 기술
선택에 우선한다.

## 2. 목표

- 자연어 질의 → SQL 실행 → 결과 표/차트 응답까지 한 번의 대화로 완결
- 생산계획 시뮬레이션(라인 배치, 수요 변동 등)을 대화 중 실행하고 결과 비교
- 도메인 지식(테이블 스키마, KPI 정의, 원인 진단 규칙)을 에이전트가 정확히
  참조하도록 구조화 — 잘못된 컬럼/KPI 해석으로 인한 오답 방지
- 대화 이력 관리(편집/재생성 포함)로 시행착오 비용을 낮춤
- 폐쇄망 배포 가능 — 외부 CDN/폰트/API 의존 없이 사내망에서 완결

## 3. 비목표 (out of scope, 현재 기준)

- 생산계획 데이터의 **쓰기(write)** — 조회·시뮬레이션만 지원, SQL 실행
  도구는 읽기 전용 가드레일을 강제한다
- 간트차트·파이차트 등 현재 범위 밖 시각화 유형
- 다중 사용자 권한/조직 구조 (현재 단일 세션 단위 대화만 고려)
- 모바일/반응형 UI (사내 데스크톱 사용 전제)

## 4. 사용자 · 핵심 시나리오

| 사용자 | 시나리오 |
| --- | --- |
| 생산계획 담당자 | "지난달 B라인 불량률 추이 보여줘" → 표/차트 응답 |
| 현장 관리자 | "설비 A 다운되면 이번 주 물량 어떻게 되지?" → 시뮬레이션 실행 → 결과 비교 |

## 6. 비기능 요구사항

- **폐쇄망 배포**: 외부 CDN·폰트·API 의존 금지, 신규 의존성은 오프라인
  반입 가능 여부를 먼저 확인. 빌드 산출물에 하드코딩된 외부 URL이 없어야 함
- **데이터 계약 안정성**: 에이전트-프론트 간 이벤트 스키마, 도구 결과
  형식이 바뀌면 백엔드·프론트를 함께 갱신해야 함 — 한쪽만 바뀌는 것을
  방지하는 절차 필요
- **보안**: SQL 실행 도구는 읽기 전용 가드레일 필수, API 키·DB 비밀번호 등
  민감정보는 버전관리에 포함하지 않는 설정 파일에만 보관

1. ~~도메인 지식 1단계~~ — 완료
2. ~~대용량 결과 저장 (백엔드)~~ — 완료
3. **대용량 결과 저장 (프론트엔드)** — 착수 가능, 미착수
4. **차트 v2 (최종 답변 차트)** — 3번 완료 후 착수
5. **채팅 UI 라이브러리 정합성 후속 조치** — 병행 가능, 백엔드 의존 없음
6. 도메인 지식 추가/검토 UI, 2·3단계 — 우선순위 미정, 사용자 피드백 후 확정

## 8. 열린 질문

- 조회 결과의 컬럼 성격(수치/범주/시간 등) 추론 정확도가 결과 저장·차트
  기능 모두의 공통 리스크로 언급됨 — 별도 조사 필요 여부 미정
- 도메인 지식 추가/검토 UI의 요구사항이 아직 문서화되지 않음 — 2단계
  범위와 통합할지, 별도로 다룰지 결정 필요
- 사이드바 컴포넌트 구현이 두 갈래로 남아있어 통합 여부 미정
- 실제 사내 서비스(DB/시뮬레이션 연동)로의 전환 일정 미정
